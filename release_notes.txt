####################################################
###       Release: ngPost v5.6                   ###
###       date:    2026/09/23                    ###
####################################################

ngPost v5.6 is a major feature, security, resilience, and performance release.
It introduces sequential multi-tab posting with global queue controls, an interactive
UI zoom level controller with dynamic interface scaling, a guided PAR2 configuration
dialog supporting modern parity engines (ParPar, MultiPar, par2j), deep NZB post
verification with redundancy analysis, external configuration merging, an official
headless build and Docker container, comprehensive VPN and credential security
hardening, yEnc 1.3 compliance, and significant performance optimizations across
the NNTP streaming pipeline and SQLite history store.

====================================================
1. FUNCTIONAL CHANGES (Partie fonctionnelle)
====================================================

--- New features and Removals (Nouveautés et suppressions) ---

- In-app update validation and reliability:
  * Native Linux, Windows and macOS update tests now cover notification,
    download verification, process handoff, replacement, restart and rollback.
  * Release archives are exercised by the current installer and the unmodified
    5.5.1 updater before publication; Windows Setup also validates a real upgrade.
  * Fixed Windows update failures when flushing the transaction journal or
    inheriting the installation directory as the updater process working directory.
  * Source builds, AppImages and Setup-managed installs announce updates in red
    in the status bar, with a clickable version-specific release link. Portable
    installations keep their existing Install and Restart popup.
  * Update dialogs hold automatic shutdown during the update interaction.
- Sequential Multi-Tab Posting & Global Queue Controls:
  * "Post all" button added to submit all prepared Quick Post tabs sequentially
    into a managed posting queue (_pendingJobs), automatically focusing the first
    submitting tab.
  * Global Pause, Resume, and Stop controls added in the header to safely pause
    or cancel running and queued tasks across all tabs.
  * Harmonized control styling with compact 16x16 circular action icons (stop,
    pause, play).
- Guided PAR2 Configuration Dialog (Par2SettingsDialog):
  * Dedicated modal dialog accessible from the Options menu or posting tabs.
  * Extended parity engine support: par2cmdline, ParPar (with automatic OpenCL
    GPU acceleration detection), MultiPar, and par2j (64-bit).
  * Dynamic block count guidance preventing the 32,768 source block limit in
    par2j / MultiPar on large posts.
  * Custom argument support via PAR2_ARGS_CUSTOM preserving user-defined flags
    without automatic GUI overwrites.
  * Engine-specific argument validation executed at configuration load time.
- Advanced NZB Integrity Verification (--check / --check_json):
  * Post integrity assessment based on residual PAR2 recovery packets, yielding
    clear verdicts (ProbablyRecoverable, Unrecoverable, Undetermined).
  * Stable, script-friendly process exit codes: 0 (complete), 1 (missing but
    recoverable via PAR2), 2 (unrecoverable / missing beyond repair), 3 (inconclusive /
    preflight failure).
  * Pure JSON machine report mode (--check_json) on stdout with diagnostics
    routed to stderr.
  * Early exit (early-stop) mechanism terminating checks immediately once a post
    is mathematically proven unrecoverable.
  * File-by-file damage accounting reporting exact residual redundancy percentage.
- Configuration Merging on Save (saveConfig):
  * Saving configuration merges external edits made to ngPost.conf (comments,
    custom flags, reordered keys) instead of blindly overwriting the file.
- Persistent Filename Obfuscation:
  * Added CLI flag --obfuscate_filename (--obfuscate-filename) and persistent
    multi-value configuration key 'obfuscate = article, filename'.
- Pinned Startup Tab:
  * Ability to designate the default tab to display on startup via the tab bar
    context menu, highlighted with a bold tab title (StartupTabBar).
- Interactive UI Zoom Level Control:
  * Discrete status bar affordance featuring a seamless magnifying glass icon and
    real-time zoom percentage badge (e.g. 100%).
  * Clicking the icon toggles a compact popup slider anchored directly above the
    status bar, with quick-reset to 100% and automatic dismissal on click-outside or Escape.
  * Comprehensive interface scaling from 80% to 150%: dynamically scales typography,
    buttons, inputs, spinboxes, headers, and table row heights across all tabs.
  * Debounced persistence in ngPost.conf (UI_ZOOM) restoring user zoom preference across
    sessions, saved silently without cluttering the activity log.
  * Proportional tab dimensions and padding (em/ex metrics) adapting gracefully to
    custom font scaling and High-DPI screens, with tab bar height and scroll buttons
    dynamically matching corner posting controls.
- Inline Clipboard Copy Actions:
  * Quick-copy buttons with animated tooltips added to generated NZB name and
    archive password fields.
- Collapsible Posting Log Pane:
  * Transparent overlay toggle button anchored beside the tab bar to collapse
    and restore the posting log splitter.
  * Collapsed by default on startup with saved geometry in ngPost_gui.ini, and
    automatic uncollapse whenever an error is logged (logError()).
- Official Headless Build & Docker Container:
  * Dedicated compile flag (CONFIG+=no_hmi) stripping all GUI, X11, and OpenGL
    dependencies for minimal headless server and NAS deployments.
  * Official minimal container image based on Debian trixie-slim published to
    ghcr.io, running as an unprivileged user (1000:1000) with a read-only root,
    bundled with 7-Zip and par2cmdline.
  * Pre-created /config and /data mount points owned by 1000:1000 so named or
    anonymous volumes inherit unprivileged ownership out of the box.
  * Upgrading from the 5.5.x image, which ran as root: the files it wrote in the
    mounted config/ and data/ folders belong to root. Run
    `chown -R <uid>:<gid> config data` once, for the user the container runs as
    (1000:1000, or the one given with --user), before starting 5.6.
- Removals:
  * Removed obsolete build scripts: src/ngPost_cmd.pro, src/makeAppImage_cmd.sh,
    and src/makeAppImage.sh.
  * Removed dead macros (__RELEASE_ARTICLES_WHEN_CON_FAILS__) and unused code in
    Poster (prepareArticlesInAdvance, _prepareNextArticle) and NntpArticle (body()).

--- Improvements (Améliorations) ---

- Main Tab Ergonomics & Navigation:
  * Logical tab ordering: History (tab 0), Folder Monitoring (tab 1), Quick
    Post (tab 2+), and trailing "+" tab.
  * Monotonic Quick Post numbering (Post #1, Post #2, ...): tab closing never
    reuses active IDs while tasks are running; counter resets only when idle.
  * Progress header label decoupled from active tab view: continuously displays
    the task actively transferring in the background.
  * High-contrast styling and visual queue badges for pending tabs.
- Unified External Tool Resolution (ExternalToolResolver):
  * Deterministic search prioritizing bundled tools shipped alongside ngPost
    before scanning system PATH.
  * Graceful fallback with warning to automatic discovery when a configured custom
    path is missing, rather than failing silently.
- Archive Volume Size Limits:
  * Supported maximum RAR volume size limit (RAR_SIZE_MAX).
  * Suppressed redundant volume size adjustment logs when requested size is zero.
- History Table Column Management:
  * Interactive column resizing with debounced persistence in ngPost_gui.ini and
    a context-menu action to reset column widths.
- Folder Monitoring (FoldersMonitorForNewFiles):
  * Batch file stabilization using shared polling rounds instead of sequential
    delays per file.
- Precise Diagnostic Timestamps:
  * Prefixed all GUI, file, and CLI logs with millisecond timestamps [hh:mm:ss.zzz]
    while preserving clean machine-readable outputs for JSON commands.
- Unified Log File Location:
  * Centralized ngPost.log in the user configuration directory across Linux,
    macOS, and Windows.

--- Bug Fixes (Corrections / Fix) ---

- Staging Recovery on Preparation Failure:
  * Restores original source files back into the GUI tab and cleans up temporary
    compression directories if archive preparation fails before transfer starts.
- Safe Obfuscation & Monitored File Deletion:
  * Prevented monitored folder loop where restored obfuscated filenames were
    detected as new files and re-posted.
  * Guarded --rm_posted against deleting original source files if their obfuscated
    counterparts failed to restore.
  * --rm_posted and the Auto tab's "delete once posted" no longer delete the
    sources of a post with failed or unconfirmed articles (behaviour inherited
    from v4.1): the files stay in place for a resume from the history. Temporary
    archives keep their own rules.
- Stop All and Close All Tabs:
  * The Stop button is shown only while a post is in progress. Otherwise a
    "Close all tabs" cross takes its place: after a confirmation, it closes every
    Quick Post tab and empties Quick Post #1; new tabs are numbered from #2 again.
  * Stopped tabs can be posted again from scratch with "Post all tabs" or their
    own button: the user's sources are restored, the NZB the stop left behind is
    replaced without a question, the stopped post's temporary archives are
    removed, and its history entry is closed. A stopped post resumed from the
    History tab in the meantime is left untouched.
  * Used kernel rename calls to prevent silent cross-filesystem file copies (EXDEV).
- Safe Auto-Shutdown Guarding (holdShutdown()):
  * Auto-shutdown is strictly gated: only triggers if at least one article was
    successfully uploaded since the option was armed.
  * Scoped hold prevents shutdown while modal dialogs (file pickers, settings,
    confirmations) are open or unposted tabs remain in the queue.
  * Manual task cancellation never triggers automatic machine shutdown.
- Default Tab Closure Logic:
  * Hardened tab closure on default Quick Post tab to cleanly reset inputs rather
    than producing invalid UI states.
- Wayland & Offscreen Splitter Fixes:
  * Resolved splitter mouse-grab and resizing issues under Wayland and KDE Breeze.
- PAR2 Empty Output Detection:
  * Aborts post with an explicit error when a PAR2 tool exits with code 0 but
    generated zero recovery files.
- MultiPar Byte Limits & Arguments:
  * Corrected byte calculations and block limits passed to MultiPar and par2j.
- Log Formatting Fixes:
  * Stripped unintended HTML tags from PostingJob log messages.

====================================================
2. SECURITY HARDENING (Sécurité)
====================================================

--- New features and Removals (Nouveautés et suppressions) ---

- Official Security Policy (SECURITY.md):
  * Published formal vulnerability reporting procedures, disclosure guidelines,
    and defined the dual-branch maintenance model (stable-security, devel-security).
- Machine-Wide VPN Routing Lease:
  * Machine-wide routing lease preventing interface and routing table collisions
    across concurrent instances (VPN_LEASE_WAIT_MINUTES, VPN_RECOVERY_MAX_ATTEMPTS).
- Keyless Release Provenance & Checksums:
  * Enforced published SHA-256 release checksums and automated supply-chain
    provenance attestation (SLSA) on all build artifacts.

--- Improvements (Améliorations) ---

- Strict Credential & Secret Masking (SecretMasker):
  * Automatic redaction of archive and proxy passwords glued to command-line
    switches (-p, -hp) in all logs and console output; verified by unit tests.
- Cryptographically Secure Password Generation:
  * Archive passwords generated directly from OS entropy (QRandomGenerator::system())
    using unbiased rejection sampling.
- Filesystem & Configuration Access Control:
  * Restricted SQLite history database (history.db, -wal, -shm) and configuration
    files to 0600 permissions (0700 for directory) on POSIX.
  * Applied protected Windows DACLs granting access exclusively to the caller's SID.
  * Automatic startup repair of insecure permissions on legacy installations.
- Verified Application Updates:
  * Cryptographic signature and SHA-256 hash verification for update manifests,
    with strict download enforcement limited to trusted GitHub domains.

--- Bug Fixes (Corrections / Fix) ---

- Windows WireGuard Tunnel Hardening:
  * Staged WireGuard profiles in %ProgramData%\ngPost\wg under protected ACLs
    (SYSTEM and Administrators only) to eliminate TOCTOU privilege escalation.
  * Sanitized WireGuard configurations (WireGuardConfigPolicy) by rejecting command
    execution directives (PreUp, PostUp, PreDown, PostDown).
  * Safely serialized elevated PowerShell arguments and enforced system binary paths.
  * Handled UAC prompt cancellations (Win32 error 1223 / ERROR_CANCELLED) gracefully.
  * Verified Service Control Manager (SCM) service state before tunnel teardown.
- Linux Privileged VPN Helper Hardening (Protocol v2/v3, Revision 4):
  * Helper verifies that the calling user possesses read permissions on configuration
    and authentication files before root opens them, preventing local exfiltration.
  * Validated Polkit caller identity before generating authorization rules.
  * OpenVPN credentials streamed over helper stdin and stored only on volatile
    /run storage with owner-only permissions.
  * Revoked legacy Polkit authorizations automatically during helper upgrades.
- OpenVPN Configuration Policy:
  * Strict directive whitelist enforced before elevation, blocking dangerous
    directives such as 'plugin' or directory traversal paths.
  * Rejected positional credentials on http-proxy/socks-proxy and denied
    http-proxy-user-pass.
  * Stripped profile routing directives (redirect-gateway, route) to preserve
    host network routing integrity.
- NNTP Authentication Failure Circuit Breaker:
  * Aborts upload task after 3 consecutive backoff cycles with rejected server
    credentials, avoiding provider account lockouts.
- NNTP Framing & Injection Prevention:
  * Strict Message-ID format validation and centralized command serialization
    ensuring exactly one CRLF delimiter, neutralizing header injection risks.

====================================================
3. THE REST: PERFORMANCE, ARCHITECTURE & QUALITY (Le reste)
====================================================

--- New features and Removals (Nouveautés et suppressions) ---

- Function Length Enforcement (Lizard Ratchet):
  * CI enforcement of function complexity and physical line bounds (<= 100 lines
    for new functions, hard ceiling at 200 lines) locked in function-length-baseline.txt.
- Static Analysis & Memory Sanitizer Workflows:
  * Integrated Clang-Tidy (.clang-tidy) and Cppcheck static analysis pipelines.
  * Added automated AddressSanitizer (ASan) and UndefinedBehaviorSanitizer (UBSan)
    testing workflows in CI.
- Pinned Test Count Floors:
  * Pinned minimum test pass counts per platform in tests/expected-counts.txt to
    prevent test omissions or silent suite skipping.

--- Improvements (Améliorations) ---

- yEnc Encoding Performance:
  * Single memory allocation for complete yEnc article bodies (=ybegin, headers,
    data, =yend), reducing allocator traffic from 6.44 MB to 1.46 MB per article.
  * Fixed buffer sizes calculated against provable mathematical worst cases.
- NNTP Pipeline & Socket Throughput:
  * Socket writes pass precalculated wire lengths (_bodyWireSize), eliminating
    redundant strlen() calls across 700 KB buffers.
  * Thread-local seeded pseudo-random engines (std::mt19937) for Message-ID
    generation, eliminating mutex contention.
  * Reduced lock scope in Poster: queue lock held strictly during article enqueue.
- SQLite History Database Performance:
  * Set synchronous=NORMAL under WAL mode, eliminating redundant fsync operations.
  * Schema v5 migration: post_articles table converted to WITHOUT ROWID to index
    directly on (file_id, part).
- GUI Responsiveness & Memory Bounding:
  * Log pane document capped to 5,000 blocks with disabled undo history.
  * Log block insertion bounded to 2,048 characters to prevent layout freezes.
- Code Modernization & Architecture:
  * Major modularization of monolithic classes (NgPost, PostingJob, MainWindow,
    NntpConnection, VpnManager, Par2Settings, NzbCheck, NzbHistoryRegenerator)
    into focused, cohesive components.
  * Decomposed monolithic routines across PAR2 settings validation, VPN profile
    enforcement, Windows security audits, and NZB recovery into discrete helpers
    conforming to the <= 100-line function complexity gate.
  * Replaced raw buffer pointers with std::unique_ptr<char[]> in NntpArticle.
- Complete Internationalization (i18n):
  * Full translation updates and 100% catalog completion across all seven
    supported languages: German, English, Spanish, French, Dutch, Portuguese,
    and Chinese.

--- Bug Fixes (Corrections / Fix) ---

- Strict yEnc 1.3 Compliance:
  * Escaped trailing spaces and tabs at line ends and on the final byte of an
    article with '=' as required by yEnc 1.3, preventing CRC mismatches from
    whitespace-trimming NNTP servers.
  * Padded pcrc32 checksums to 8 hexadecimal digits.
- NNTP EOF Synchronization:
  * Poster waits for in-flight article encoding to complete before concluding EOF,
    preventing premature socket disconnects and stalled uploads.
- Event Loop Starvation Prevention:
  * Bounded socket read buffer size during network signal processing to preserve
    Qt event loop responsiveness.
- Memory Leaks & Undefined Behavior:
  * Fixed QChart axis memory leak during statistics chart refresh.
  * Fixed QTranslator memory leak on application exit.
  * Cleaned up file list model connections in PostingWidget destructor.
  * Resolved integer overflow under UBSan in yEnc test suite.
- Windows Offscreen CI Geometry:
  * Configured virtual offscreen display (2560x1440) for headless GUI tests,
    fixing test window clamping issues on Windows CI runners.
- Strict Warning-Free Compilation:
  * Enforced CONFIG+=ngpost_werror (-Werror / /WX) across all builds, with MSVC
    external header suppression via /external:anglebrackets.

Notes de version (Français) :

ngPost v5.6 est une version majeure combinant de nouvelles fonctionnalités, un
durcissement complet de la sécurité, une meilleure résilience des transferts et
des optimisations substantielles de performances. Elle introduit notamment la file
d'attente séquentielle multi-onglets avec contrôles globaux, un réglage interactif
du niveau de zoom de l'interface avec mise à l'échelle dynamique, un dialogue guidé
de configuration PAR2 supportant les moteurs modernes (ParPar, MultiPar, par2j), une
vérification approfondie de l'intégrité des NZB avec calcul de réparabilité, la
fusion intelligente de la configuration, un binaire headless officiel et son
image Docker, la conformité yEnc 1.3, ainsi qu'une révision complète de la
sécurité VPN et de l'isolation des identifiants.

====================================================
1. PARTIE FONCTIONNELLE
====================================================

--- Nouveautés et suppressions ---

- Validation et fiabilité de la mise à jour intégrée :
  * Les tests natifs sous Linux, Windows et macOS couvrent désormais la notification,
    la vérification du téléchargement, le passage de témoin entre processus (handoff),
    le remplacement des fichiers, le redémarrage et la restauration (rollback).
  * Les archives de publication sont testées avec le programme d'installation actuel
    ainsi qu'avec l'ancien outil 5.5.1 non modifié avant publication ; l'installeur
    Windows valide également une mise à niveau réelle.
  * Correction des échecs de mise à jour sous Windows lors du vidage du journal de
    transaction ou de l'héritage du dossier d'installation comme répertoire de travail
    de l'installeur détaché.
  * Les versions compilées depuis les sources, les paquets AppImage et les installations
    gérées par l'installeur annoncent les mises à jour en rouge dans la barre d'état, avec
    un lien cliquable vers la release correspondante. Les installations portables conservent
    leur boîte de dialogue d'installation et de redémarrage.
  * Les dialogues de mise à jour suspendent l'extinction automatique du système durant
    l'interaction utilisateur.
- Envoi séquentiel multi-onglets & contrôles globaux de file :
  * Ajout du bouton « Poster tout » pour soumettre séquentiellement l'ensemble des
    onglets « Post rapide » préparés dans une file d'attente gérée (_pendingJobs),
    en donnant automatiquement le focus au premier onglet soumis.
  * Ajout de commandes globales Pause, Reprise et Stop dans l'en-tête permettant
    de suspendre ou d'interrompre l'ensemble des posts actifs et en attente.
  * Harmonisation visuelle des contrôles avec des icônes circulaires compactes 16x16
    (stop, pause, lecture).
- Boîte de dialogue guidée des paramètres PAR2 (Par2SettingsDialog) :
  * Nouveau dialogue dédié accessible depuis le menu Options ou les onglets de post.
  * Prise en charge élargie des moteurs : par2cmdline, ParPar (avec détection
    automatique de l'accélération GPU OpenCL), MultiPar et par2j (64 bits).
  * Calcul dynamique et recommandations pour éviter le dépassement de la limite de
    32 768 blocs sources imposée par par2j / MultiPar sur les gros volumes.
  * Prise en charge des arguments personnalisés via PAR2_ARGS_CUSTOM, préservés
    sans écrasement par l'interface graphique.
  * Validation des arguments spécifiques au moteur choisi dès le chargement de la
    configuration.
- Vérification approfondie de l'intégrité des NZB (--check / --check_json) :
  * Évaluation de l'intégrité basée sur les paquets de récupération PAR2 résiduels,
    produisant un verdict clair (ProbablyRecoverable, Unrecoverable, Undetermined).
  * Codes de retour stables et documentés : 0 (complet), 1 (incomplet mais
    réparable avec PAR2), 2 (irrécupérable / au-delà de la redondance), 3 (non concluant /
    échec pré-vol).
  * Mode JSON pur (--check_json) sur stdout avec redirection des journaux sur stderr.
  * Arrêt anticipé (early-stop) dès qu'un post est mathématiquement prouvé
    irrécupérable, évitant de vérifier inutilement des dizaines de milliers d'articles.
  * Décompte rigoureux des blocs endommagés par fichier avec rapport du pourcentage
    de redondance réel préservé.
- Fusion automatique de la configuration à l'enregistrement (saveConfig) :
  * Préserve les modifications manuelles externes apportées à ngPost.conf
    (commentaires, options avancées, clés réorganisées) lors des sauvegardes GUI/CLI.
- Persistance de l'offuscation des noms de fichiers :
  * Nouvelle option en ligne de commande --obfuscate_filename (--obfuscate-filename)
    et support de la clé combinée 'obfuscate = article, filename'.
- Épinglage de l'onglet de démarrage :
  * Possibilité de définir l'onglet ouvert par défaut au démarrage via le menu
    contextuel, mis en évidence par un intitulé en gras (StartupTabBar).
- Réglage interactif du niveau de zoom de l'interface (UI Zoom) :
  * Intégration discrète dans la barre d'état avec icône loupe sans contour et badge
    affichant le pourcentage de zoom en temps réel (ex. 100 %).
  * Clic sur l'icône ouvrant une fenêtre popup avec curseur (slider) aux dimensions
    adaptées, ancrée directement au-dessus de la loupe, avec réinitialisation rapide à 100 %.
  * Fermeture intuitive automatique au clic en dehors de la popup ou par la touche Échap.
  * Mise à l'échelle complète de l'interface de 80 % à 150 % : adapte dynamiquement la
    taille des polices, boutons, champs de saisie, spinboxes, en-têtes et hauteur des lignes
    de tableaux sur l'ensemble des onglets.
  * Mémorisation temporisée dans ngPost.conf (UI_ZOOM) restituant le niveau de zoom choisi
    à chaque démarrage, enregistrée silencieusement sans polluer le journal d'activité.
  * Dimensions et marges des onglets dimensionnées proportionnellement aux métriques de police
    (unités em/ex) pour un rendu net et homogène sur les écrans haute densité (HiDPI), avec
    alignement dynamique de la hauteur de la barre et des boutons de défilement sur les
    contrôles d'envoi.
- Boutons de copie rapide dans le presse-papiers :
  * Boutons de copie inline avec infobulle et confirmation visuelle pour le nom du
    fichier NZB et le mot de passe de l'archive.
- Volet rétractable du journal de post (Posting Log) :
  * Bouton transparent repliable ancré à côté des onglets pour masquer/afficher
    le séparateur de journal.
  * Replié par défaut au démarrage (état mémorisé dans ngPost_gui.ini) et ouverture
    automatique dès qu'une erreur de post survient (logError()).
- Binaire Headless officiel & conteneur Docker :
  * Option de compilation dédiée (CONFIG+=no_hmi) supprimant toute dépendance
    graphique X11/Widgets pour les serveurs et NAS.
  * Image Docker officielle basée sur Debian trixie-slim publiée sur ghcr.io,
    exécutée sous utilisateur non-privilégié (1000:1000) avec système de fichiers
    root en lecture seule, incluant 7-Zip et par2cmdline.
  * Pré-création des dossiers /config et /data avec propriétaire 1000:1000 dans l'image
    pour un fonctionnement immédiat avec les volumes nommés sans conflit de permissions.
  * Mise à jour depuis l'image 5.5.x, qui tournait en root : les fichiers qu'elle a
    écrits dans les dossiers montés config/ et data/ appartiennent à root. Lancez
    une fois `chown -R <uid>:<gid> config data`, pour l'utilisateur du conteneur
    (1000:1000, ou celui donné par --user), avant de démarrer la 5.6.
- Suppressions :
  * Suppression des anciens scripts et profils de compilation : src/ngPost_cmd.pro,
    src/makeAppImage_cmd.sh et src/makeAppImage.sh.
  * Suppression de la macro obsolète __RELEASE_ARTICLES_WHEN_CON_FAILS__ et du
    code mort dans Poster et NntpArticle.

--- Améliorations ---

- Ergonomie et navigation dans les onglets :
  * Disposition logique : Historique (0), Surveillance de dossiers (1), Post

  * Centralisation de ngPost.log dans le répertoire de configuration d'ngPost sur

--- Corrections (Fix) ---

- Restauration des fichiers en cas d'échec de préparation :
  * Restauration automatique des fichiers sources dans l'onglet de post et nettoyage
    du dossier temporaire si la compression ou la préparation échoue avant le début
    du transfert.
- Sécurisation de l'offuscation et de la suppression des sources :
  * Élimination de la boucle de surveillance où la restauration d'un nom offusqué

- Arrêt et fermeture de tous les onglets :

  * Utilisation d'appels de renommage atomiques au niveau du noyau pour empêcher

- Sécurisation de l'extinction automatique du PC (holdShutdown()) :

    l'armement de l'option.
  * Verrou de sécurité empêchant l'extinction tant qu'une boîte de dialogue modale
    (fichiers, paramètres, confirmation) est ouverte ou que des onglets préparés
    attendent dans la file.
  * Une annulation manuelle de post ne déclenche jamais l'extinction.
- Fermeture propre de l'onglet de post par défaut :
  * Réinitialisation cohérente des contrôles de l'onglet par défaut au lieu de
    laisser des états d'interface invalides.
- Correctifs pour Wayland et environnements offscreen :
  * Correction du redimensionnement du panneau de log et des conflits de capture
    souris sous Wayland et KDE Breeze.
- Détection des échecs PAR2 sans fichier généré :
  * Interruption immédiate du post en cas de code retour 0 d'un outil PAR2 n'ayant
    produit aucun fichier de parité.
- Limites de blocs et calculs MultiPar :
  * Correction des calculs en octets et des limites de blocs transmis à MultiPar
    et par2j.
- Formatage des journaux :
  * Nettoyage des balises HTML résiduelles dans les messages de PostingJob.

####################################################
###       Release: ngPost v5.5                   ###
###       date:    2026/08/27                    ###
####################################################

This release contains every user-visible change made since the stable
ngPost v5.4.2 release.

Major new features:

- ngPost can now generate a post information file after each post from a
  user-provided text model. ngPost remains independent of every third-party
  index format: an index can distribute its own model without requiring a
  fork or index-specific code in ngPost.
- The feature is disabled until POST_INFO_TEMPLATE is set. POST_INFO_OUTPUT
  selects the destination, and POST_INFO_ONLY_ON_SUCCESS defaults to true so
  failed or partial posts are not exported accidentally.
- Models can mix plain text and variables on the same line. A line whose first
  character is '#' is a comment and is not written. The renderer supports 26
  fixed variables, plus `__date:<format>__`, `__dateStart:<format>__` and
  `__meta:<name>__`. Available facts include the source name, final NZB path,
  archive name and password, poster, groups, PAR2 percentage, payload size,
  article counters, status, speed, duration and ngPost version.
- A model can also be a JSON or an XML document. The format is declared on a
  line of its own, "#!json" or "#!xml", or taken from the name of the model
  when it ends in .json or .xml; a declaration wins over a name, including an
  unrecognised one, which is reported rather than guessed at. ngPost then
  escapes every value it inserts for that format, so a value containing a quote
  or an ampersand can no longer produce an invalid file. Escaping applies to
  inserted values only: the braces, tags and field names written in the model
  are left untouched. A model without a declaration escapes nothing, allowing
  a text model to use any separator and any wording. Output paths and post
  command arguments are never escaped. A ready-made JSON model is provided
  under templates/.
- `__postSize__` reports the payload files plus PAR2 data before yEnc, excluding
  an .nfo copied alongside the archive. The historical `__sizeInByte__` variable
  remains available unchanged for existing scripts.
- Users can attach their own fields to a post, such as a title, portal link or
  category. --post_meta keeps a field local to the generated file; -m/--meta,
  or the GUI "Also in NZB" box, additionally publishes it in the NZB. Publishing
  is always explicit because an NZB may circulate outside the local machine.
- `--export_post_info <id>` can generate a file for a post already present in the
  history, either to a selected path or to stdout. The same action is available
  from the History tab.
- Ready-made generic, Baselien and JSON models are included under templates/.
  A full beginner guide is available on the wiki in English and French.
- Models and output files may live anywhere accessible to the user. Relative
  paths from ngPost.conf are resolved from that configuration file's folder.
  Generated files are written atomically; the model, NZB and source paths are
  protected against accidental replacement, including aliases through
  symlinks and case-insensitive filesystems. Automatic and manual exports also
  refuse to overwrite the SQLite database, its WAL/SHM companions or the legacy
  CSV history. A file containing the archive password is restricted to its
  owner where the platform allows it.
- `POST_INFO_OUTPUT` accepts all non-secret placeholders. Secret values such
  as `__rarPass__` are deliberately refused in a file or directory name.

Configuration folder:

- The configuration folder no longer depends on the name of the program file.
  It is now always "ngPost": ~/.config/ngPost on Linux, %LOCALAPPDATA%\ngPost
  on Windows, ~/Library/Application Support/ngPost on macOS. Previously the
  folder was named after the executable, so an AppImage - which is renamed on
  install and on every update - started with an empty configuration and an
  empty post history, and a CLI post could land in a different history from
  the one the GUI displayed. Nothing changes for an install already using the
  canonical name; the paths are identical.
- On first start with the new version, ngPost looks once for a configuration
  left in an old, name-derived folder and brings it over: configuration, post
  history reference, GUI settings, post information models and VPN profiles.
  It tells you what it adopted and from where. The application is already
  running on the new folder when it does: nothing to restart, nothing else to
  do.
- The operation is deliberately conservative. It never runs if the new folder
  already contains configuration or history data, never overwrites an existing
  file, never follows symbolic links and never deletes anything. Configuration
  assets are copied atomically rather than moved, so a script or cron job using
  `-c <old folder>/ngPost.conf` still reads the same settings, models included.
  One thing does change for such a script: that file has no POST_DB line, so it
  records its posts in the database of the new folder while the adopted
  configuration keeps using the old one -- two histories instead of one. ngPost
  now says so, at adoption time and again on every run that passes that file,
  and tells you the two ways out: point the script at the new configuration, or
  add POST_DB to the old file. The SQLite
  database and its WAL files stay at their existing path and the adopted config
  continues to reference them: migration is immediate even for several GB and
  never manipulates a potentially live database. When the old folder is
  writable, the previous configuration is also snapshotted as
  `ngPost.conf.save`, or a timestamped `.save` variant if that name exists.
- A completed adoption or recorded decision is one-shot. Its outcome is stored
  in `<config folder>/.ngPost_config_migration`, so it does not run again even
  if the configuration is later changed or removed. A failed attempt changes no
  authoritative file, stops startup before the new folder is used and is safely
  retried later. If several old folders exist, only one is adopted - the one
  matching the program name, otherwise the most recently configured - and the
  others are reported and left untouched.
- Inspection commands remain side-effect free: `--help`, `--version` and
  argument-parser errors do not create or migrate the configuration folder.
  Passing `-c` keeps the selected configuration fully explicit and does not
  trigger adoption. CLI migration diagnostics go to stderr and cannot corrupt
  JSON, NZB or other structured stdout output.

History and migration:

- ngPost no longer creates a history database it does not use. It used to
  create one, fully populated with tables and permanently empty, at the
  default path on every single start - `--help` and `--version` included - even
  when POST_DB pointed elsewhere. This could create stray
  ngPost_history.sqlite files in old configuration folders. The database is
  now created on first real use, at the configured path, and a path that cannot
  be opened is reported against the path actually in use.

- The SQLite history migrates automatically and transactionally from schema
  v1 or v2 to v3 on first launch. Schema v2 adds post facts and scoped
  metadata; v3 records the exact ARTICLE_SIZE boundary needed by a safe
  resume. Existing posts are kept, and a database created by a newer ngPost is
  refused instead of being opened with an unsupported schema.
- New posts record the source name, application version, PAR2 percentage,
  prepared-payload-plus-parity size and active transfer duration. Transfer time
  is accumulated across resumes, and the original transfer start date is kept.
- Posts created before v5.5 did not record every new fact. When one of them is
  exported, unavailable values such as `__postSize__`, `__par2Pct__`,
  `__originalName__` or custom fields are left empty instead of being reported
  as a misleading zero. ngPost also reports that the export is incomplete.
- The History tab now loads entries in pages of 200, with previous/next
  controls and an "entries N-M" indicator. Histories containing many thousands
  of posts no longer need to be loaded into the interface at once. Statistics
  and resume candidates remain complete, and the resume banner refreshes with
  the rest of the history.
- A resumed post now uses the original post's poster, groups, per-file group
  choice, obfuscation settings and PAR2 description. Compression and PAR2
  generation are not run again because the files being resumed already exist.
- Resume sources are revalidated immediately before transfer. If one changed or
  disappeared while the job was waiting, the whole resume is aborted before
  anything is sent and the post remains resumable.
- The article size used by the original attempt is frozen in history and reused
  by a resume. Changing ARTICLE_SIZE between attempts can therefore no longer
  renumber segments or combine different byte ranges in one NZB. A missing,
  inconsistent or non-positive article size is rejected before anything is sent.
- Generated files and post hooks receive the consolidated description of the
  whole resumed post, not only the files or articles transferred by the latest
  attempt. `__avgSpeed__` remains the speed of the latest transfer attempt;
  the duration, size, paths and article counters are cumulative.
- Final NZBs are regenerated atomically and only from complete, consistent
  history. A resume writes its partial stream to a private temporary file; if
  history finalisation or consolidation fails, the previous NZB is left intact
  and no post-info file, upload or hook is launched with incomplete data.
- When password storage is disabled, a resume recovers the advertised password
  from the existing NZB. If neither history nor that NZB can supply it, the
  resume stops before transfer instead of silently publishing a consolidated
  NZB without the password.
- Failures before the first article is sent now finish their history entry as a
  terminal, non-resumable failure instead of leaving a phantom "posting" row.

Automation and post hooks:

- All post-information settings are now available from the command line, so a
  scripted or containerised run does not require ngPost.conf:
  --post_info_template, --post_info_output,
  --post_info_only_on_success / --no_post_info_only_on_success,
  --no_post_info, --post_meta and --export_post_info.
- Post-command and NZB-upload settings are also available from the command
  line: repeatable --nzb_post_cmd, --post_cmd_timeout,
  --post_cmd_fail_is_error / --no_post_cmd_fail_is_error,
  --post_cmd_expose_password / --no_post_cmd_expose_password,
  --nzb_upload_url, --nzb_upload_timeout and --post_history. Command-line post
  commands replace, rather than append to, commands from the configuration.
- NZB_POST_CMD uses the same variable renderer as post information models.
  Substitution is performed in one pass, so text contained in a substituted
  value is never interpreted as another variable.
- Command lines are split into arguments before variables are replaced. A
  substituted path or value containing spaces, quotes or apostrophes therefore
  remains one argument instead of changing the command structure. The legacy
  %1 alias for the NZB path remains supported in post commands.
- Fixed non-secret values are also provided as NGPOST_* environment variables.
  Dates are available as NGPOST_DATE, NGPOST_DATE_START and
  NGPOST_DATE_EPOCH. Arbitrary metadata and the complete description are stored
  in the temporary JSON file named by NGPOST_JSON, avoiding lossy environment
  variable name conversions.
- Post commands now use one FIFO queue across posts and run sequentially in the
  order configured. The NZB upload finishes and releases the file before that
  post's commands begin, so a hook may safely move or rename it.
- Each queued post-action lot keeps its own timeout, failure and secret-exposure
  settings. Editing the configuration while an earlier lot is still running
  cannot change that lot or expose one of its secrets.
- ngPost waits for NZB uploads and post commands before exiting or shutting the
  machine down. A VPN failure also passes through this completion barrier.
  Ctrl+C still interrupts immediately.
- Command start failures, crashes, non-zero exit codes and bounded stdout/stderr
  output are now reported. POST_CMD_FAIL_IS_ERROR optionally turns a hook
  failure into a non-zero ngPost result.
- POST_CMD_TIMEOUT controls hung commands (0 means no limit), while
  NZB_UPLOAD_TIMEOUT defaults to 300 seconds for stalled uploads.
- The substituted command is logged, but archive passwords are redacted.
  Passwords are excluded from inherited environment variables and from the JSON
  by default; POST_CMD_EXPOSE_PASSWORD explicitly enables them. Using
  `__rarPass__` as a command argument remains supported.

GUI and translations:

- Each posting tab now has one discreet "Create a post info file" checkbox and
  a button opening the model editor. Auto Post offers the same controls, with
  one choice applied to that run.
- The editor separates the model from the values of the current post. The model
  is displayed line by line with its name, content and live preview; custom
  fields stay in a separate table and are never written into the model.
- Model lines and custom fields can be added or removed, and "Save as..." can
  create a new model without using an external text editor. Unsaved model
  changes are confirmed before leaving because posts always read the file on
  disk.
- A built-in reference lists every supported variable, its meaning and whether
  its value is known before or only after posting. Secret values are shown only
  as present, never displayed.
- Models opened during the session remain available to later posting tabs and
  may be removed from the list. "Use this model for my next posts too" can make
  the selected model the configured default.
- A post can also be written somewhere other than what POST_INFO_OUTPUT says.
  The "Write it to:" field is empty by default and shows the configured
  destination in grey, meaning the post follows it, including any later change
  to the configuration. Typing a path, or picking a folder, applies to that
  post only, and the line underneath resolves the variables so the real path
  is visible before posting. "Use this model for my next posts too" saves the
  destination together with the model.
- Posting controls have been reorganised around two clear decisions: what the
  post produces and how its payload is packed. Compression volume settings,
  the RAR limit and PAR2 redundancy now follow their corresponding controls;
  archive name and password fields have more room, and the NZB path expands to
  use the available width.
- "NZB Password" has been renamed "Archive password", matching what the value
  actually represents and the `__rarPass__` variable used by models and hooks.
- All interface catalogues have been refreshed in English, French, Spanish,
  German, Dutch, Portuguese and Chinese. The accumulated unfinished entries
  from previous releases are translated, and the embedded .qm files have been
  regenerated.

Fixes and compatibility:

- The update check now follows the channel of the build it runs in. A stable
  install asks GitHub for its latest stable release, as before. A pre-release
  build asks for the list instead, because what supersedes it may be a newer
  unstable build or the stable it leads to -- neither of which the "latest"
  endpoint ever returns. Release ordering understands a pre-release suffix:
  v5.5 supersedes v5.5-unstable.20260824.107.abc, never the other way round,
  and two unstable builds of one version are ordered by the date and run
  number in their tag. Without this, anyone running an unstable build would
  have been told they were up to date forever, including once the stable of
  the same number was published. AppImages are unaffected: they update through
  zsync, which was already channel-aware.

- A queued posting job now keeps the settings captured when it was created
  instead of silently adopting global settings changed while it waited.
- A post containing a whole unreadable file is now reported as partial instead
  of successful. Such a file creates no failed article, so checking article
  failures alone was insufficient.
- --meta and --post_meta split key/value pairs on the first '=' only, so URLs
  and other values containing '=' are accepted. Empty or malformed keys and a
  key declared with conflicting scopes are reported.
- Metadata values are stored as entered and escaped only when the NZB is
  written, preserving apostrophes, ampersands and Unicode in generated files.
- Public custom metadata is preserved when the final NZB is regenerated from
  history. Private metadata never enters the delivered NZB.
- `-m "password=..."` now follows the same history-secret policy as an archive
  password without changing archive encryption: it honours
  `HISTORY_STORE_PASSWORDS`, is removed by password purging and is included in
  a regenerated NZB only when password publication is requested.
- History started_at now records the actual beginning of transfer rather than
  job creation, and a resume no longer overwrites the first attempt's date.
- The history now follows the final NZB path when an existing destination makes
  ngPost rename the file to `<name>_1.nzb`.
- Exports to stdout contain only the generated data; configuration messages,
  warnings and diagnostics are sent to stderr so pipelines remain valid. JSON
  and XML exports use the same comment removal and value escaping as file
  exports.
- Archive passwords are no longer printed by posting debug/completion logs.
  Upload diagnostics now omit URL credentials, paths, queries and response
  bodies, and response data is drained continuously instead of accumulating in
  memory.
- Windows VPN teardown now follows the OpenVPN management connection after the
  interactive-service pipe closes, and a backend startup failure explicitly
  stops the partial tunnel before releasing it. ngPost no longer launches the
  Linux privileged cleanup helper on Windows.
- Editing a WireGuard profile on Windows now updates its tunnel service as one
  transaction and rolls back both service and file on failure. VPN profile
  imports are written atomically with owner-only permissions, reject filename
  collisions, and preserve the previous profile if credentials or registration
  fail.
- Upload cancellation and timeout are safe even when Qt emits completion
  synchronously, and a verbose upload response is drained without unbounded
  memory growth.
- Configuration saves are atomic, and resume planning refuses to use history
  when queued article events could not be flushed to SQLite.

###       Release: ngPost v1.0                   ###
###       date:    2019/08/24                    ###
####################################################

First release of the implementation
cf README:

command line usenet poster for binaries developped in C++/QT
it is designed to be as fast as possible and offer all the main features to post data easily and safely.

Here are the main features and advantages of ngPost:
    it can use several servers (using config file) with each several connections (supporting ssl)
    it is spreading those connection on several threads. By default the number of cores of the station but you can set the number if you fancy.
    it is using asynchronous sockets in the upload threads
    it is preparing the Articles on the main Thread (yEnc encoding) so the upload threads are always ready to write when they can. (each connections has 2 Articles ready in advance)
    it is limiting the disk access to the minimum by opening the files to post only once in the main Thread and processing them sequentially one by one (no need to open several files at the same time)
    it can do full obfuscation of the Article Header (subject and msg-id)
    it is generating a random uploader for each Article Header (from) but can use a fixed one if desired
    it is of course generating the nzb file
    it can support multiple files and multiple folders
    there is an handler on interruption which means that if you stop it, you'll close properly and generate the nzb for what has been posted
    in case of interruption, it will list the files that havn't been uploaded so you can repost only those ones and then manually concatenate the nzb files
    you can add meta in the header of the nzb (typically for a password)
    ...

What it does not:
    compress or generate the par2 for a single files (use a script to do it ;))
    retry posting articles (not really needed as the msg-id of the articles are generated using UUID (followed by @ that you can configure (by default @ngPost))
    retry to connect when a connection is lost as they are all created with the KeepAliveOption set. If we loose all the connections, ngPost close properly and write the nzb file

RQ: you don't need to obfuscate the file names as they will only be used in the nzb file as the obfuscation is done for each Article with a UUID as subject and msg-id.
